# Validate feature args against the downloaded schema.json

Each `prefapp/features` package ships a Draft-07 `schema.json` (generated from `config.yaml`) describing its user-feedable `$arg`s, but the renderer never validated `featureArgs` against it, so a typo'd or wrong-typed arg silently fell back to defaults. We validate the raw `featureArgs` (with the downloader-injected `traceability` key stripped) against a shallow copy of the on-disk `schema.json` with `additionalProperties: false` inside `features_renderer.render`, throwing an aggregated error on failure and skipping features without a schema with a warning. One owner at `render` covers every render path (downloads, refs, mocks) and catches arg mistakes before any file is written, while legacy and `ref`-fetched features keep rendering.

That gate is opt-in per feature: a feature opts in by setting `enable_validation: true` in its `config.yaml`, and the renderers (`render` and `getClaimPatches`) consult that flag through `isFeatureArgsValidationEnabled` before calling `validateFeatureArgs`. A feature that leaves the flag absent or false renders without schema validation, so a shipped `schema.json` can never turn into a hard failure for a feature that never asked for the check; a feature that opts in but ships no `schema.json` still warns and renders.
